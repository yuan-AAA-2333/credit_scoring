# 质量与工程化待办清单

> 记录代码质量、工程规范方面的改进方向。
> 当前状态：能跑通即可，以下按优先级排序。

---

## P0 - 高优先级

### 1. 类型提示（Type Hints）
- **现状**：函数参数和返回值无类型标注
- **改进**：为所有公共函数添加 `def func(df: pd.DataFrame) -> pd.DataFrame:` 式标注
- **价值**：IDE 自动补全、静态类型检查（mypy）、可读性提升

### 2. 文档字符串（Docstrings）
- **现状**：部分函数已有注释，但不统一
- **改进**：统一使用 Google / NumPy 风格 docstring
- **示例**：
  ```python
  def clean_fit(df_train: pd.DataFrame) -> dict:
      """在训练集上学习清洗参数。

      Args:
          df_train: 训练集DataFrame

      Returns:
          参数字典，包含各字段的中位数和截尾阈值
      """
  ```

### 3. 异常处理
- **现状**：少量 assert，无 try/except
- **改进**：关键步骤（数据加载、模型训练、文件保存）添加异常捕获和友好错误提示
- **价值**：面试时运行不会突然崩掉

---

## P1 - 中优先级

### 4. 日志系统（替代 print）
- **现状**：全部使用 print 输出
- **改进**：引入 `logging` 模块，按级别（INFO/WARNING/ERROR）输出
- **配置**：支持日志写入文件，便于排查问题

### 5. 路径管理
- **现状**：路径硬编码为相对路径字符串
- **改进**：使用 `pathlib.Path` 统一管理路径，支持跨平台
- **示例**：`Path(__file__).parent / "data" / "raw" / "lc_loan_data.csv"`

### 6. 输入校验
- **现状**：假设数据格式正确，无前置校验
- **改进**：在 `load_data` 后增加数据格式检查（列名、类型、目标变量存在性）
- **价值**：防御式编程，避免下游错误难以定位

---

## P2 - 低优先级

### 7. 代码风格统一
- **现状**：注释风格、命名习惯略有差异
- **改进**：引入 black / ruff 自动格式化，flake8 静态检查
- **配置**：添加 `.pre-commit-config.yaml`

### 8. 单元测试
- **现状**：无测试
- **改进**：为核心纯函数编写 pytest 测试用例
- **重点测试**：
  - `calc_woe_iv`：边界情况（全好/全坏样本）
  - `score_customer`：评分一致性
  - `build_bins`：分箱边界合理性

### 9. CI/CD 流程
- **现状**：无自动化
- **改进**：GitHub Actions 配置（如后续上传GitHub）
  - 自动运行 pytest
  - 自动代码风格检查
  - 自动生成测试覆盖率报告

### 10. 性能优化
- **现状**：pandas 逐行操作，未做向量化优化
- **改进**：
  - WOE 编码部分使用 `pd.map` 替代循环
  - 大DataFrame考虑使用 polars / dask
- **价值**：处理更大规模数据时性能更好

---

## 当前取舍说明

| 方面 | 当前做法 | 未做的原因 |
|------|---------|-----------|
| 日志 | print | 用户要求"print输出即可"，保持简单 |
| 类型提示 | 无 | 用户要求"能跑通即可"，降低复杂度 |
| 异常处理 | assert | 课程作业场景，数据格式可控 |
| 单元测试 | 无 | 当前为个人作品集，非生产代码 |
| 路径管理 | 字符串 | Windows环境，pathlib优势不明显 |

> 如后续转为生产项目或需要更高代码质量，可按本清单逐步迭代。
